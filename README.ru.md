Flux — лёгкий прокси-клиент для Windows на базе ядра [mihomo](https://github.com/MetaCubeX/mihomo), созданный с использованием WinUI 3 и Fluent Design.

## Скриншоты

### Главная страница

Управление системным прокси и режимом маршрутизации, просмотр активного профиля, выбранного узла, текущего трафика и состояния ядра.

### Прокси

Просмотр групп, фильтрация узлов по имени или типу, переключение узлов и проверка задержки.

![Управление прокси Flux: режимы, группы, выбор узлов и проверка задержки](screenshots/proxies.png)

На скриншотах используется демонстрационный профиль [`sample-profile.yaml`](sample-profile.yaml). Адреса серверов приведены для примера и не являются рабочими прокси.

## Возможности

- **Нативный интерфейс Windows** — WinUI 3, фон Mica, Fluent Design и несколько языков интерфейса.
- **Гибкая маршрутизация** — Режимы Rule, Global и Direct, управление системным прокси и TUN.
- **Управление профилями** — Импорт совместимых с Clash YAML-файлов или ссылок подписки, переключение профилей и обновление подписок.
- **Управление узлами** — Выбор узлов, фильтрация по имени или типу, просмотр провайдеров прокси и проверка задержки.
- **Трафик и диагностика** — Графики отправки и загрузки в реальном времени, активные соединения, правила, журналы ядра и проверка доступности сервисов.
- **Системный трей** — При закрытии окно скрывается в трей. Для выхода используйте меню трея.
- **Встроенная среда выполнения** — Дистрибутивы включают mihomo, .NET и компоненты Windows App SDK.

## Начало работы

Поддерживается **Windows 10 версии 2004 (сборка 19041) и новее** на x86, x64 и ARM64.

1. На [странице релизов](https://github.com/1595901624/flux/releases) выберите пакет для архитектуры Windows и следуйте инструкции релиза. ZIP для установки вне магазина распакуйте и запустите вложенный `Install-FluxSideload.ps1` от имени администратора.
2. Запустите Flux, откройте **Profiles**, импортируйте ссылку подписки или локальный YAML-файл и выберите профиль для активации.
3. В **Proxies** выберите узел или группу. Режим **Rule** направляет трафик согласно правилам профиля.
4. Включите **System proxy** на странице **Home**, чтобы приложения, учитывающие настройки прокси Windows, использовали Flux.

Режиму TUN нужны права администратора или работающая привилегированная служба Flux. После закрытия окна Flux продолжает работать в трее.

Неподписанные MSIX из CI предназначены для тестирования при разработке. Если доступен портативный ZIP, распакуйте его и запустите `Flux.exe`.

## Конфигурация и данные

Flux использует совместимые с Clash YAML-профили с разделами `proxies`, `proxy-groups` и `rules`. Пример: [`sample-profile.yaml`](sample-profile.yaml). Укажите собственные действительные данные сервера или ссылку подписки; Flux не предоставляет прокси-подписки.

По умолчанию настройки, профили и журналы хранятся в `%APPDATA%\flux`. Для портативной версии в каталоге с правом записи создайте перед запуском пустой файл `.config\PORTABLE` рядом с `Flux.exe`, чтобы хранить данные в `.config\flux`.

## Сборка из исходного кода

Установите [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) в Windows. Проект использует WinUI 3 и нацелен на Windows SDK `10.0.22621.0`. Для работы в IDE нужна версия Visual Studio с поддержкой .NET 10 и WinUI 3.

```powershell
git clone https://github.com/1595901624/flux.git
cd flux
dotnet restore Flux.slnx
dotnet build Flux.csproj -c Release
dotnet run --project Flux.csproj -c Release --no-build
```

Целевая платформа по умолчанию — `win-x64`. Для других архитектур укажите `-r win-x86` или `-r win-arm64`. Репозиторий содержит соответствующие ядра mihomo.

Запуск тестов:

```powershell
dotnet test tests/Flux.Tests/Flux.Tests.csproj -c Release
```

Упаковка дистрибутивов с привилегированной службой описана в [процессе сборки](.github/workflows/build-msix.yml).
