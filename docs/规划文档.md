## 3. 技术架构与公共契约

### 3.1 工程结构

在现有解决方案中建立以下项目边界：

- `Flux`：WinUI UI、页面、ViewModel 和应用启动。
- `Flux.Core`：配置模型、运行时配置合成、订阅、API、备份、更新、测试和通用业务逻辑，不引用 WinUI。
- `Flux.Service`：Windows Service，负责特权模式下启动和管理 mihomo。
- `Flux.Service.Installer`：请求 UAC 后安装、修复、卸载服务，不接受任意可执行文件或命令参数。
- `Flux.Tests`：纯单元测试和服务契约测试。
- `Flux.IntegrationTests`：mihomo、文件系统、HTTP、Named Pipe 和备份集成测试。
- `Flux.UiTests`：WinAppDriver 或 Windows Application Driver 可执行的关键流程测试。

保留 `AppServices` 作为旧页面的兼容入口，但新功能通过接口注入。完成迁移后，`AppServices` 只负责组合根，不承载业务状态。

### 3.2 核心接口

冻结以下共享契约后再允许功能 agent 并行开发：

- `ICoreManager`
  - `StartAsync`、`StopAsync`、`RestartAsync`、`ApplyConfigAsync`
  - 支持 `Sidecar`、`Service`、`Stopped`、`Faulted` 状态
  - 发布 `CoreStateChanged` 和可诊断的失败原因
- `IPrivilegeBroker`
  - 查询、安装、修复、卸载服务
  - 通过带版本号的 Named Pipe 协议管理服务内核
  - 只允许预定义操作，不允许传递任意命令
- `IMihomoClient`
  - Config、Proxy、Provider、Rule Provider、Connection、Delay、GeoData 和 Version API
  - 所有调用接收 `CancellationToken`
  - 不再吞掉异常，统一返回 `OperationResult<T>` 或带错误类型的异常
- `IMihomoStreamClient`
  - Traffic、Memory、Logs、Connections 四类订阅
  - 自动重连、指数退避、页面不可见时降频或停订阅
- `IRuntimeConfigBuilder`
  - 输入基础配置、订阅、全局增强、订阅增强、DNS/TUN 和临时链式代理
  - 输出 YAML、验证结果、每个字段的来源和增强脚本日志
- `IProfileService`
  - 导入、新建、编辑、选择、批量删除、排序、更新、全部更新、重新激活
  - 提供明确的更新通道：直连、系统代理、内核代理、自动回退
- `IBackupService`、`IUpdateService`、`IHotkeyService`、`IUnlockTestService`
- `ISettingsStore`
  - 原子保存、版本迁移、字段校验、变更事件和敏感字段加密

### 3.3 配置与数据模型

继续使用 Flux 自有 YAML 文件，但加入 `schema-version`。每次启动先备份旧文件，再执行幂等迁移。

应用设置拆为强类型子对象：

- `GeneralSettings`：语言、主题、启动页、静默启动、自动启动、轻量模式。
- `ProxySettings`：系统代理、PAC、代理主机、绕过、守护间隔。
- `CoreSettings`：内核通道、端口、LAN、IPv6、日志、接口、外部控制器和 CORS。
- `TunSettings`、`DnsSettings`、`TunnelSettings`。
- `UiSettings`：首页卡片、导航顺序、折叠、代理列数、通知位置和图标。
- `AutomationSettings`：订阅更新、延迟检测、日志清理、自动备份和应用更新。
- `BackupSettings`：本地历史及加密后的 WebDAV 配置。
- `HotkeySettings`、`TestSettings`。

订阅模型补充：

- `AllowAutoUpdate`、`DangerAcceptInvalidCerts`、`LastUpdateStatus`、`LastError`、`NextUpdateAt`。
- Merge、Script、Rules、Proxies、Groups 五类增强文件 ID。
- 远程订阅主页、更新来源、ETag、Last-Modified。
- 每次更新先写临时文件并校验；失败时保留旧文件和旧运行时配置。

敏感数据使用 Windows DPAPI CurrentUser 加密，日志和诊断包必须遮蔽订阅 URL 参数、Basic Auth、控制器 Secret 和 WebDAV 凭据。

### 阶段 2：Windows Service 与权限模型

任务 `F2-Service`：

- `Flux.Service` 以 LocalSystem Windows Service 运行，仅负责特权内核生命周期和状态查询。
- Named Pipe 使用协议版本、请求 ID、超时和 Windows ACL；只允许当前交互用户及管理员访问。
- 服务验证运行时配置路径必须位于 Flux 数据目录，内核路径必须属于已验证的内置或缓存版本。
- UI 可查询 `NotInstalled/Stopped/Running/Broken/VersionMismatch`。
- 实现安装、修复、重装和卸载；所有 UAC 操作显示动作和错误，不静默失败。
- 开启 TUN 时优先使用服务模式；没有服务且应用非管理员时引导安装服务，不直接失败。
- 服务断开时自动关闭保存的 TUN 状态，避免下次启动造成断网。

完成门禁：普通用户启用 TUN、服务重启、服务版本不匹配、异常退出恢复和卸载清理均通过。

- 每个检测器有独立超时、取消、状态和地区字段；外部响应变化时返回“未知”，不误报支持。
- 并发受限，关闭页面后取消未完成请求。

任务 `F6-Tray`：

- 托盘菜单动态显示系统代理、TUN、出站模式、订阅和代理组。
- 所有菜单状态与主界面双向同步。
- 支持单击显示窗口、单击菜单和禁用三种点击行为。
- 状态图标反映普通、系统代理和 TUN；图标切换失败不影响核心。
- 退出执行完整清理，普通关闭只隐藏窗口。

任务 `F6-Lightweight`：

- 进入轻量模式时保存窗口状态、释放主窗口和页面订阅，只保留托盘、热键、内核及必要定时任务。
- 从托盘或热键恢复时重建窗口并刷新所有状态。
- 支持关闭窗口若干分钟后自动进入；重新打开窗口取消定时器。

### 阶段 7：备份、更新、诊断和国际化

任务 `F7-Backup`：

- ZIP 备份包含应用配置、订阅、增强文件和必要状态，不包含日志、内核缓存或明文凭据。
- 本地创建、列表、删除、导入、导出、恢复。
- WebDAV 配置、上传、下载、列表、删除和恢复。
- WebDAV 凭据使用 DPAPI；诊断和界面不回显密码。
- 自动备份支持固定小时/天间隔和关键配置变化触发。
- 恢复先验证 ZIP 路径、防目录穿越和配置完整性，再原子替换并重启应用。

任务 `F7-Update`：

- GitHub Release 清单作为更新源，区分 x86/x64/ARM64。
- MSIX 使用受信任的 AppInstaller/MSIX 更新路径。
- 便携版由独立更新助手替换文件，必须校验签名或发布清单哈希，并支持失败回滚。
- 自动检查、手动检查、版本说明、跳转发布页和重大版本不兼容提示。

任务 `F7-Diagnostics`：

- 导出系统、应用、内核、配置结构、运行模式和最近日志。
- 自动遮蔽 URL Token、Secret、密码、用户名和本地敏感路径。
- 导出前显示内容清单，不自动上传。

任务 `F7-I18n`：

- 所有硬编码用户文本迁移至 `.resw`。
- 覆盖参考项目的 zh-CN、zh-TW、en、de、es、fa、id、ja、ko、ru、tr、tt、ar。
- 语言切换保存后提示重启应用；RTL 语言验证布局方向。
- 缺失翻译回退英文，再回退资源键，不能显示空文本。

### 阶段 8：集成、稳定性和发行

由集成 agent 串行完成：

- 清除旧页面直接操作文件、注册表和进程的路径，统一走服务接口。
- 对照功能矩阵逐项标记 `Implemented/Excluded/Blocked`，每个 Excluded 必须有平台理由。
- 校验窗口状态恢复、单实例、深链、静默启动、关机注销、崩溃恢复和代理还原。
- 执行 x86、x64、ARM64 的便携版和 MSIX 构建。
- 验证首次安装、覆盖升级、卸载、服务残留、自动启动和协议注册。
- 更新 README、中文 README、第三方许可证、内核版本和发布说明。
- 发布前不允许存在空事件处理器、静默异常吞噬、占位按钮或未连接的设置项。

## 5. Agent 协作规则

- 第一波只执行 `F0`、`F1-Core`、`F1-Config`，共享契约合并后才能开启后续并行任务。
- 第二波执行 `F2-Service` 和 `F3-*`。
- 第三波执行 `F4-*` 与 `F5-*`。
- 第四波执行 `F6-*`、`F7-*`。
- 最后一波只做阶段 8 集成，不并行修改核心契约。
- 每个 agent 开始前先阅读本规划、相关参考项目组件、现有 Flux 实现和上游契约。
- 每个任务必须独立提交；禁止顺手重构无关模块。
- 两个 agent 不得同时修改同一页面、配置模型或核心接口。
- 新设置、新命令或新事件必须先补模型和测试，再接 UI。
- 每个 agent 的交付说明必须包含：实现项、未实现项、接口变化、测试命令、手工验证和风险。
- 合并顺序始终为：模型与契约 → 服务 → ViewModel → UI → 测试与文档。

## 6. 测试与验收标准

自动化测试至少覆盖：

- 配置默认值、版本迁移、未知字段、损坏文件和原子保存。
- 每层 Merge 顺序、数组语义、Script 成功/异常/超时、DNS/TUN 和链式代理合成。
- mihomo 校验失败后的运行配置回滚。
- Core 并发启动/停止/重启、异常退出、服务断开和回退。
- 订阅 gzip、BOM、Unicode、Basic Auth 空密码、TLS 错误、超时、超限、304、无效 YAML 和证书选项。
- 定时更新、全部更新、取消、重复操作和失败状态。
- 所有 URI 协议解析与 YAML 往返。
- 系统代理/PAC/绕过/守护及应用异常退出恢复。
- Named Pipe ACL、协议版本、非法路径和非法操作拒绝。
- Provider、Rule Provider、连接关闭和 WebSocket 重连。
- 备份路径穿越、损坏 ZIP、WebDAV 失败和恢复回滚。
- 更新清单、架构选择、哈希失败和便携版回滚。
- 敏感信息遮蔽。
- ViewModel 搜索、排序、筛选、取消和页面卸载。
- 关键 UI 流程：首次启动、导入订阅、切换节点、启用系统代理、安装服务、启用 TUN、编辑配置、备份恢复和退出。

发布验收：

- Release 构建零警告。
- 所有测试通过，无不稳定重试测试。
- 三种架构均能生成便携 ZIP 和 MSIX。
- 空配置、普通订阅、Provider 订阅和大型订阅均可运行。
- 启用代理后强制结束 UI、停止服务或系统注销，不遗留导致断网的系统代理。
- 主窗口反复打开关闭、切换七个以上页面和运行一小时后无持续内存增长。
- 所有可见按钮、菜单和设置均有实际行为、错误提示和持久化结果。

## 7. 最终完成定义

只有同时满足以下条件，才能宣布完成 Clash Verge Rev 2.5.2 的 Windows 功能复刻：

- 功能矩阵中全部 Windows 适用项均已实现并通过验收。
- 平台不适用项和 WinUI 技术替代项均有书面说明。
- 普通用户无需以管理员身份启动 Flux 即可通过服务模式使用 TUN。
- 所有配置变更均可验证、回滚并在重启后恢复。
- 所有网络、文件、服务和更新失败都有用户可理解的提示。
- 不泄露订阅 Token、控制器 Secret 或 WebDAV 凭据。
- 文档、测试、三架构发行物和第三方许可证同步完成。
- 不以“后续补充”“暂未支持”或不可操作的占位 UI 作为完成状态。
